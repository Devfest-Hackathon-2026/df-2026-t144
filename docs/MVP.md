# MICHI? — 今日のMVP

決定日：2026年11月8日。企画仕様書v0.1は検討資料として扱い、今日動かす版では以下の範囲に絞る。

## 確かめたい体験

「目的地へ行く途中、少し寄り道してでも『？』の正体を知りたくなるか」を確かめる。移動の目的を保ったまま、近づく・発見する・物語を読む・次の場所が気になる、という一巡を作る。

主対象はiOS・AndroidのReact Nativeアプリ。Expo SDK 58を採用する。React Native Webは同じUIの確認用で、ネイティブアプリ完成の判定には用いない。

## 今日採用する範囲

| 項目 | 今回の範囲 |
| --- | --- |
| 地域 | 京都三条・高瀬川周辺を仮置き。正式な地域は未決定 |
| 目的地 | 京都市役所前、四条河原町の2件。座標は計画用の概略位置 |
| スポット | 一之船入、池田屋騒動址、瑞泉寺、三条大橋の擬宝珠、駅伝の碑の5件 |
| 寄り道 | 追加5分／10分。見学は1スポット1分として追加時間に含める |
| 発見前 | 「？」と短いヒントで、名称・物語を隠す |
| 現地解放 | 45m以内。位置情報が60秒以内、報告精度が60m以内のときに発見ボタンを有効化 |
| 発見後 | 固定の短文、一次資料へのリンク、関連スポットを表示 |
| 図鑑 | 端末内に保存。デモと現地の履歴を分離し、再起動後に復元 |
| 地図 | ネイティブ地図。WebプレビューはUI確認用の略図 |

半径・精度・見学時間は初期設定値であり、実地検証を通じて調整する。三条大橋の代表点と駅伝の碑は近接するため、同じ立ち寄りで両方を発見できることがある。駅伝の碑は橋から続く関連発見として扱い、別の遠い立ち寄りとして時間を水増ししない。

## デモと現地の違い

| | 体験デモ | 現地で歩く |
| --- | --- | --- |
| 現在地 | 三条京阪付近からの仮想位置 | 許可を得て取得する実GPS |
| 移動 | 「デモでここへ移動」で再現 | 実際の移動で位置が更新 |
| 経路 | 固定時間と地点を結ぶ概略線 | 接続後はGoogle Routesの徒歩経路 |
| 未接続時 | APIキーなしで操作可能 | 近くのスポットの解放は可能。実経路は表示しない |
| 履歴 | デモとして記録 | 現地として記録 |

現地モードの発見は、カメラで対象物を認識した証明ではなく、GPSによる近接判定。位置情報が取れない場合は再取得またはデモへの切替を案内する。現地の履歴を、デモ移動によって解除しない。

現在地はアプリ利用中だけ取得する。Google経路を探す操作時に、現在地を経路サーバーとGoogleへ送信する。図鑑は端末内保存のみで、クラウド同期・アカウント連携は行わない。

## 実装済みと未検証

実装済みは、画面遷移、目的地・予算選択、デモ経路、未発見表示、GPS近接判定、発見詳細、出典、関連候補、図鑑保存、およびGoogle Routes接続用サーバー。自動チェックは`pnpm typecheck`、`pnpm test`、`pnpm test:server`で再実行できる。

次はまだ検証していない。

- iOS・Android実機での地図、位置情報許可、精度、復帰時の動作、図鑑の再読込。
- 認証情報を設定したGoogle Routesとの実通信と、返された道の実際の通行可否。
- 現地の安全に立ち止まれる位置、史跡代表点から対象物までの距離、開門状況。
- ユーザーが寄り道を選ぶか、物語を面白いと感じるか、次の発見へ進むか。

デモを通せたことと、現地で使えることを別々に判定する。位置・時間が仮データのデモを実地成功として数えない。自動テストも実機テストや実API接続の代わりにはならない。

## 後回しにする機能

| 機能 | 次に検討する条件 |
| --- | --- |
| カメラ・AR | 近接だけで成立する体験を確かめた後、見る対象を見つける助けになるか検証 |
| ログイン・クラウド同期 | 機種変更や複数端末の履歴共有が必要になった段階 |
| Geminiによる推薦・解説 | 固定の検証済み事実と出典を入力にし、出力の評価方法を決めた後 |
| ユーザー投稿 | 内容・位置の確認と更新の運用を決めた後 |
| 自由な目的地検索 | 固定2目的地で経路比較を確認した後 |
| 広域展開・高度な最適化 | 現地のスポット密度と、寄り道を選ぶ反応を確かめた後 |

## 次の3ステップ

1. 実機で、起動→「？」→発見→図鑑→再起動後の復元まで確認する。Expo Goの対応SDKと、iOS実機の同一Expoアカウント条件を合わせる。[Expo公式の起動案内](https://docs.expo.dev/get-started/start-developing/)
2. Google Routesを接続し、2目的地で通常・探索ルートを比較する。エラー時に仮経路へ置き換えないことと、見学込みの追加時間上限を確認する。[接続メモ](GOOGLE-CLOUD.md)、[Google公式の経路計算](https://developers.google.com/maps/documentation/routes/compute_route_directions)
3. 対象地域を確定し、少人数で歩く。寄り道を選んだか、解放に成功したか、2件目へ進んだかを観察し、座標・ヒント・物語を調整する。[現在のスポット出典](SOURCES.md)
